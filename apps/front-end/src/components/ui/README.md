# components/ui (shadcn)

Components in this folder are generated by the shadcn CLI. This app is an existing
React app with its own SCSS-based design system
(`src/assets/styles`), so Tailwind's preflight reset (which shadcn
components are built assuming) is **not** enabled globally - doing so
would silently restyle raw HTML tags across the whole app
(headings, links, lists, buttons, etc. losing their browser-default
styling wherever the legacy CSS doesn't already override them).

Instead, preflight is scoped to a `shadcn-scope` class (see
`src/tailwind.css`) via a CSS `@scope` block, so the reset only applies
inside elements that carry that class.

## What you need to do when adding a new shadcn component

Add `shadcn-scope` to the `className` of **every DOM root the component
renders**, the way `button.tsx` does:

```tsx
<ButtonPrimitive
  className={cn("shadcn-scope", buttonVariants({ variant, size, className }))}
  {...props}
/>
```

This is not automatic - the shadcn CLI has no idea `shadcn-scope` exists,
so it won't add it for you.

- **Components rendered via a portal** (e.g. `Dialog`, `Popover`,
  `Tooltip`, `DropdownMenu`, `Select`) mount their content outside the
  normal DOM tree, typically on `document.body`. That portal content is a
  separate root and needs `shadcn-scope` applied to it directly - putting
  the class on the trigger element is not enough.
- **Components composed entirely from other already-scoped primitives**
  (e.g. something built out of `<Button>`) don't need it added again -
  they inherit the reset from the inner primitive. Only add it where a
  component renders raw HTML (or a primitive that isn't scoped yet)
  directly.
